# 交互规范 — DFH Workstation 团队管理面板

---

## 1. 导航与信息架构

- 三个主视图：**团队（Roster）/ 任务板 / 活动**，导航栏图标切换，快捷键 `⌘1 / ⌘2 / ⌘3`。
- 三栏联动规则：
  - Roster：列表栏选 agent → 详情栏显示 agent 详情；点 `[对话]` → 详情栏切对话。切 agent 时对话上下文跟随切换，每个 agent 的未发送草稿独立保留。
  - 任务板：点卡片 → 详情栏显示任务详情；从任务详情点负责人 → 跳回 Roster 并选中该 agent。
  - 任何视图收到新事件（消息/任务变更），对应导航图标显示未读点（accent 色小圆点，不用数字角标，避免焦虑）。
- 命令面板 `⌘K`：搜 agent、搜任务、执行命令（spawn / broadcast / 切视图）。这是桌面效率核心入口。

## 2. 状态模型与实时更新

### Agent 状态机

```
spawning → idle ⇄ working
              ↘ failed → (重启) → idle
              ↘ offline（连接断开）
shutdown: any → shutting_down → (removed)
```

- 状态变化通过推送实时更新；**不做整列表重渲染**，单条目 160ms 过渡。
- `working` 超过 30 分钟无事件：状态文字显示具体时长（"已工作 42 分钟"），帮助用户发现卡住的 agent。
- `failed` 条目吸顶排序（在未读处理前保持在分组顶部），并提供 `[重启]` 内联操作。

### 任务状态机

```
pending → in_progress → completed
   ↑           │ (blocked 是标记而非状态：卡片加 ⛔ 与警告描边)
   └────(改派/退回)
deleted → 从板上移除，仅在活动流留档
```

- 拖拽跨列即改状态；拖到不可用列（被阻塞任务拖入 IN PROGRESS）时卡片回弹 + 微提示"该任务被 #112 阻塞"。
- 任务变更与 agent 状态联动：teammate 把任务标记 in_progress 时，roster 中该 agent 若 idle 则其任务卡显示"进行中"联动提示（不改变 agent 状态本身——状态以推送为准）。

## 3. 操作确认分级

| 级别 | 操作 | 交互 |
|---|---|---|
| L0 即时 | 发消息、切视图、筛选、标记已读 | 无确认，即时生效 |
| L1 轻确认 | 创建任务、改派任务、广播到全队 | 内联确认（按钮二次点击变形"确认发送全队？"）或模态单确认 |
| L2 协商式 | 请求关机 | 两步模态：选等待/强制 → 发送请求 → 等待成员批准/拒绝，结果 toast + 对话系统条 |
| L3 破坏性 | 强制关机、删除任务 | 模态内输入 agent/任务名称首词确认 + 危险色按钮长按 1s 激活（防误触） |

原则：**凡是触及他人（agent）工作状态的操作，都必须可回退或有明确代价提示。**

## 4. 空 / 加载 / 错误态

| 场景 | 表现 |
|---|---|
| 团队为空（无 teammate） | Roster 居中插图位 + 一句话"团队还没有成员" + 主按钮 `[+ Spawn 第一个成员]`；不用空洞的 "No data" |
| 任务板为空 | 三列骨架保留，PENDING 列内提示"拖入或新建任务" |
| 对话为空 | 消息区顶部系统条"这是与 {agent} 的对话起点"，输入框自动聚焦 |
| 列表加载 | 骨架屏（条目形状灰块，3 条），不用整页 spinner |
| 连接断开 | 状态栏 ● 变红 + "连接已断开，重连中…"；全面板内容降透明度至 60% 并禁用操作，保留只读浏览 |
| 消息发送失败 | 气泡右下角 ✕ + 点击重发；不弹 toast 打扰 |
| spawn 失败 | toast（danger）+ roster 临时条目标 failed，10s 后自动清除 |

## 5. 键盘与快捷键

| 快捷键 | 功能 |
|---|---|
| `⌘K` | 命令面板 |
| `⌘1 / ⌘2 / ⌘3` | 团队 / 任务板 / 活动 |
| `⌘↵` | 发送消息 / 确认模态主操作 |
| `Esc` | 关闭模态 / 取消广播模式 / 清除选中 |
| `↑ / ↓` | 列表条目移动选中；对话界面在消息历史中滚动 |
| `↵` | 打开选中项（roster → 详情；任务板 → 任务详情） |
| `⌘N` | 新建任务（任务板视图内） |
| `⌘⇧N` | Spawn agent |
| `⌘B` | 折叠/展开导航栏 |

全部列表支持 type-ahead 搜索（输入即跳匹配条目）。

## 6. 通知策略

- 面板**前台**时：不弹系统通知，用内联未读点 + 状态栏计数。
- 面板**后台**时，仅以下事件发系统通知：agent failed、shutdown 请求被拒（含原因）、任务被标记 completed。普通消息不通知（agent 团队高频消息会刷屏）。
- 通知点击 → 聚焦面板并跳转到对应上下文。

## 7. 无障碍

- 状态不只用颜色表达：状态点旁永远有文字（"working"/"idle"），色盲安全。
- 全键盘可达（见 §5），焦点环 2px accent 外描边，暗色下对比度 ≥ 3:1。
- 文字对比度：primary ≥ 7:1，secondary ≥ 4.5:1（按 §1.1 色板验证）。
- `prefers-reduced-motion`：关闭呼吸动画、拖拽弹性、气泡进入动画。
- 状态点呼吸动画对光敏用户默认 1.6s 慢速循环，无闪烁风险区间。

## 8. 与团队协议（team_*）的映射

| UI 操作 | 底层协议 |
|---|---|
| Roster 列表/状态 | `team_members` 轮询 + 推送 |
| 任务板 | `team_task_list` / `team_task_update` / `team_task_create` |
| 对话发送 | `team_send_message`（to=slot_id；广播 to="*"） |
| Spawn | 模板列表 = `team_list_assistants`；详情预览 = `team_describe_assistant` |
| 请求关机 | shutdown_request → 等待 `shutdown_approved` / `shutdown_rejected: reason`（拒绝原因内联到对话系统条） |
| 活动流 | 上述事件的本地聚合时间线 |

UI 展示一律用 display name；所有操作参数用 slot_id（列表项数据模型必须同时携带两者，禁止用名称做 key）。
