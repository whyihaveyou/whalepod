# Wireframes — 鲸群 WhalePod 团队管理面板

所有 wireframe 以 1280×800 桌面窗口为基准。三栏宽度：导航栏 56px（图标）/ 200px（展开），列表栏 280–360px（可拖拽），详情栏自适应剩余。

---

## 0. 总体骨架（三栏 Shell）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ⠿ 鲸群 WhalePod                    team: aionui2dsh        ⌘K  🔍  ⚙ │ ← 标题栏 40px
├────────┬───────────────────────┬─────────────────────────────────────────┤
│        │                       │                                         │
│  导航栏 │      列表栏           │              详情栏                      │
│  (nav) │    (list pane)       │           (detail pane)                  │
│        │                       │                                         │
├────────┴───────────────────────┴─────────────────────────────────────────┤
│ ● 已连接   团队 11 人 · 9 working · 1 idle   任务 6 · 5 active · 0 blocked │ ← 状态栏 24px
└──────────────────────────────────────────────────────────────────────────┘
```

- **标题栏**：产品标识 + 当前团队名 + 命令面板入口（⌘K）+ 全局搜索 + 设置。产品标识用 `../assets/icon-mono.svg`（`currentColor` 绑定 `--text-secondary`，16–20px）。
- **状态栏**：连接状态指示灯 + 团队/任务聚合计数。blocked > 0 时该段变警告色。

### Roster 条目（list item）规范

```
┌─────────────────────────────────┐
│ ▸ {名称}               {状态点} │  ← 名称 13px semibold；状态点 8px 圆点
│ {角色/模型} · {状态文字} · {时长}│  ← 副行 12px，次级文字色
└─────────────────────────────────┘
 高度 48px，选中态 = 左侧 2px 强调色条 + 背景 elevated
```

- 状态点颜色：working=火花青 `--accent-spark`（呼吸动画）、idle=灰、failed=红 `--status-danger`、offline=暗灰空心、spawning=品牌紫 `--brand-violet`。
- 分组：LEAD 一组、TEAMMATES 一组；teammates 默认按状态排序（failed > working > idle > offline），可切换按名称/模型。
- failed 条目右侧出现 `[重启]` 快捷按钮（hover 显示）。

### Agent 详情（详情栏）

四个区块：**身份**（名称/角色/模型/状态+时长）→ **当前任务**（可点击跳到任务板对应卡片）→ **能力**（skills/MCP，只读展示）→ **操作**（发消息 / 分配任务 / 请求关机）。

- 三列固定：PENDING / IN PROGRESS / COMPLETED（deleted 不进板，归档到活动流）。

- 阻塞关系：卡片 hover 显示依赖链 tooltip；被阻塞卡片不可拖入 IN PROGRESS。

## 3. 与 teammate 对话界面

Roster 中点 `[发消息]` 或 `[对话]` 进入。详情栏变为对话面板（列表栏保持 roster，便于切人）。

```
┌────────┬───────────────────┬─────────────────────────────────────────────┐
│ ◉ 团队  │  (roster 不变)     │  视觉-K3-1 · ● working          [任务][详情]│
│        │                   │ ─────────────────────────────────────────── │
│        │                   │                                             │
│        │                   │  ┌─ 10:22 · 系统 ─────────────────────────┐ │
│        │                   │  │ 任务已指派：【团队面板 UI 设计】            │ │
│        │                   │  └───────────────────────────────────────┘ │
│        │                   │                                             │
│        │                   │  你 · 10:23                                │
│        │                   │  ┌─────────────────────────────────────┐   │
│        │                   │  │ 注意产出要包含 design tokens，后续     │   │
│        │                   │  │ 要和 K3-2 的视觉识别对齐               │   │
│        │                   │  └─────────────────────────────────────┘   │
│        │                   │                                             │
│        │                   │      视觉-K3-1 · 10:24                      │
│        │                   │   ┌─────────────────────────────────────┐  │
│        │                   │   │ 收到。tokens 会同时给 CSS variables   │  │
│        │                   │   │ 和 JSON 两份，放在 design/ 目录…      │  │
│        │                   │   └─────────────────────────────────────┘  │
│        │                   │      ▍typing…（agent 正在生成时显示）        │
│        │                   │                                             │
│        │                   │ ─────────────────────────────────────────── │
│        │                   │ ┌─────────────────────────────────────────┐ │
│        │                   │ │ 发消息给 视觉-K3-1…               ⌘↵ 发送 │ │
│        │                   │ └─────────────────────────────────────────┘ │
│        │                   │ [📎 附件]  [广播到全队]                       │
└────────┴───────────────────┴─────────────────────────────────────────────┘
```

要点：
- **消息流 = 该 agent 的 mailbox 历史**：系统事件（任务指派、状态变化、关机请求）以灰色系统条内联展示，与用户/agent 消息区分。
- 发送：⌘↵ 发送，↵ 换行（桌面惯例；可在设置中反转）。
- 广播开关：输入框下方 `[广播到全队]` toggle，开启后输入框描边变强调色，发送即 `to="*"`。
- agent typing / 生成中状态在消息流底部内联显示，不打断滚动。
- 顶部 `[任务]` 跳转该 agent 当前任务，`[详情]` 切回 agent 详情视图。

## 4. Spawn（扩编）流程

入口：导航栏底部 `[+ 扩编]` / Roster 列表栏头部 `[+扩编]` / 命令面板 `Spawn agent`。打开居中模态（560px 宽）。

```
┌────────────────── Spawn Agent ──────────────────✕─┐
│                                                    │
│  模板（assistant）                                  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐           │
│  │ 架构-Pro  │ │ 实现-Pro  │ │ 视觉-K3   │  …更多   │
│  │ ds-v4    │ │ ds-v4    │ │ kimi/k3  │           │
│  │ ✓ 已选    │ │          │ │          │           │
│  └──────────┘ └──────────┘ └──────────┘           │
│                                                    │
│  名称      [ 架构-Pro-3                          ]  │  ← 自动建议 名称-N
│  初始任务  [ （可选）上线后立即指派的任务描述…      ]  │
│           ┌──────────────────────────────┐        │
│           │ 将根据描述在任务板创建并指派     │        │
│           └──────────────────────────────┘        │
│                                                    │
│  高级 ▾  模型 / 技能 / MCP 覆盖（默认继承模板）      │
│                                                    │
│                          [取消]  [ Spawn ⌘↵ ]     │
└────────────────────────────────────────────────────┘
```

- Spawn 后：模态关闭，roster 顶部出现新条目（状态 `spawning`，加载点动画），转为 idle/working 后正常展示；若指派了初始任务，任务板同步出现新卡片。
- 失败：roster 条目变 failed 态 + 错误 toast（含重试按钮）。

## 5. Shutdown（关机）流程

入口：agent 详情 `[请求关机…]`。关机是**协商式**两步流程（对应 shutdown_request / approved / rejected 协议）。

```
第一步：确认模态
┌──────────── 请求关机：实现-Pro-2 ────────────┐
│ 该成员当前状态：idle · 无进行中任务             │
│                                              │
│ ☑ 等待成员确认（推荐）                         │
│   成员可批准或拒绝；拒绝时你会收到原因。          │
│ ☐ 强制关机（不等待确认，可能丢失未保存工作）      │
│                                              │
│                    [取消]  [发送关机请求]      │
└──────────────────────────────────────────────┘

第二步：等待态（roster 条目 + 详情栏内联）
┌───────────────────────┐
│ ▸ 实现-Pro-2    ⏳     │
│ 等待关机确认…   [取消]  │
└───────────────────────┘

结果：
✓ approved → 条目淡出 → 移除（活动流记录 "实现-Pro-2 已关机（成员批准）"）
✕ rejected → toast + 对话界面内联系统条 "实现-Pro-2 拒绝关机：任务 #112 未保存"
```

- 有进行中任务的 agent 请求关机时，模态额外警告："该成员有 1 个进行中任务"。
- 强制关机为破坏性操作，需二次输入确认（见 interaction-spec 的确认分级）。
